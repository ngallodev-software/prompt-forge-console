# Existing Behavior

## Settings
- Kanban binding already exists in backend-managed settings
- The current UI can show workspace scope, but it is easy to miss
- Workspace discovery comes from the Kanban base URL

## Intake
- Intake rows already show source note path and project context
- The path is visible, but route meaning is not

## Intake Detail
- Detail page is the right place to show the full route explanation
- This should explain why the note went to Kanban or queue

## Dashboard
- Attention queues already show operational state
- Fallback/review state should be reflected there too

## Brownfield takeaway
- The UI already has the right surfaces
- The work is to clarify meaning and fallback state
